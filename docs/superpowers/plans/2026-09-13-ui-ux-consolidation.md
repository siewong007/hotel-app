# UI/UX Consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans (inline) or subagent-driven-development to implement task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Eliminate the audited UI duplications — dead pages, twin ledger payment dialogs, the reports-surface triplication — and regroup the sidebar around staff tasks.

**Architecture:** Frontend-only (`hotel-web-fe`). Nav regroup edits `routeRegistry.tsx` + `navGroups.ts` + en/ms `nav.json`. Reports converge on `/insights` (server catalog already covers all 14 legacy report types); print parity is ported to `ReportShell` before the `/reports` redirect. The two ledger payment dialogs merge into one mode-switched `RecordPaymentDialog` that keeps both backend endpoints.

**Spec:** `docs/superpowers/specs/2026-09-13-ui-ux-consolidation-design.md`
**Audit:** `docs/superpowers/specs/2026-09-13-ui-ux-consolidation-audit.md`

## Global Constraints

- Do NOT touch `src/features/rooms/config.ts` (dirty — another session's in-flight work) or `hotel-app-be/database/seed_voucher_audit.sql` (untracked, in-flight).
- `git status --short` before every commit; stage only files this plan touched.
- No new dependencies. No route-path changes except `/reports` → redirect (precedent: `/promotions`). `/admin-portal` stays a working alias — it is the staff-app cross-document entry.
- No backend, permission-name, or API-shape changes. `route_access_policies` DB untouched — nav grouping is frontend-only.
- i18n key parity: every `groups.*` key change goes in BOTH `en/nav.json` and `ms/nav.json`.
- Gates before done: `bun run typecheck && bun run lint && bun run test && bun run build` in `hotel-web-fe/`.
- `routeTree.gen.ts` is generated by the vite plugin — regenerate via `bun run build` (or `bunx tsr generate`) after route edits, then commit the result.
- ES2024 lib; never `toISOString().split/.slice` (lint-banned) — use `src/utils/date.ts`.
