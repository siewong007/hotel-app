# v0.2.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish and deploy repository release `v0.2.0` from a verified `master` commit, including the existing macOS desktop artifact.

**Architecture:** Version metadata changes are intentionally limited to the backend and web projects; the desktop application remains at `1.0.0`. The existing push CI and production workflow validate and deploy the release commit before an immutable annotated tag triggers the existing desktop build, after which GitHub Release publication attaches that build.

**Tech Stack:** Git, GitHub CLI, GitHub Actions, Rust/Cargo, React/TypeScript/Vite, Bun, Tauri

## Global Constraints

- Set `hotel-app-be` to exactly `0.2.0`.
- Set `hotel-web-fe` to exactly `0.2.0`.
- Keep all desktop version fields at exactly `1.0.0`.
- Create repository tag `v0.2.0`; do not alter `v0.1.0`.
- Add no dependencies and change no application behavior, API, schema, or infrastructure.
- Do not tag until local checks, push CI, production deployment, and public health verification pass.
- Do not publish the GitHub Release until the tag-triggered desktop build and artifact download succeed.

---

## File Map

- Modify `hotel-app-be/Cargo.toml`: backend package version.
- Modify `hotel-app-be/Cargo.lock`: resolved local backend package version generated by Cargo.
- Modify `hotel-web-fe/package.json`: web package version.
- Preserve `hotel-web-fe/bun.lock`: Bun does not store the root package version, so dependency resolution must remain unchanged.
- Preserve `hotel-desktop/package.json`: desktop JavaScript package version remains `1.0.0`.
- Preserve `hotel-desktop/src-tauri/Cargo.toml`: desktop Rust package version remains `1.0.0`.
- Preserve `hotel-desktop/src-tauri/tauri.conf.json`: desktop application version remains `1.0.0`.
- Use `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`, and `.github/workflows/desktop-build.yml` unchanged as remote gates.

### Task 4: Tag and Verify the Desktop Build

**Files:**
- No source file changes
- Remote workflow: `.github/workflows/desktop-build.yml`

**Interfaces:**
- Consumes: production-verified `RELEASE_SHA`
- Produces: immutable remote tag `v0.2.0` and downloaded macOS aarch64 build artifact

- [ ] **Step 1: Create and verify the annotated tag locally**

```bash
test "$(git rev-parse HEAD)" = "$RELEASE_SHA"
git tag -a v0.2.0 "$RELEASE_SHA" -m "Release v0.2.0"
test "$(git rev-list -n 1 v0.2.0)" = "$RELEASE_SHA"
```

Expected: annotated tag `v0.2.0` resolves exactly to `RELEASE_SHA`.

- [ ] **Step 2: Push only the release tag**

```bash
git push origin refs/tags/v0.2.0
```

Expected: remote tag `v0.2.0` is created without moving `master`.

- [ ] **Step 3: Wait for the tag-triggered desktop build**

```bash
gh run list --workflow "Desktop Build" --branch v0.2.0 --event push --limit 1
gh run watch "$(gh run list --workflow "Desktop Build" --branch v0.2.0 --event push --limit 1 --json databaseId --jq '.[0].databaseId')" --exit-status
```

Expected: the macOS aarch64 build concludes `success`. Record its run ID as `DESKTOP_RUN_ID`.

- [ ] **Step 4: Download and package the desktop artifact**

```bash
RELEASE_TMP_DIR="$(mktemp -d)"
gh run download "$DESKTOP_RUN_ID" --name hotel-desktop-macos-aarch64 --dir "$RELEASE_TMP_DIR/artifact"
find "$RELEASE_TMP_DIR/artifact" -type f -maxdepth 8 -print
tar -C "$RELEASE_TMP_DIR/artifact" -czf "$RELEASE_TMP_DIR/hotel-desktop-v0.2.0-macos-aarch64.tar.gz" .
shasum -a 256 "$RELEASE_TMP_DIR/hotel-desktop-v0.2.0-macos-aarch64.tar.gz"
DESKTOP_SHA256="$(shasum -a 256 "$RELEASE_TMP_DIR/hotel-desktop-v0.2.0-macos-aarch64.tar.gz" | awk '{print $1}')"
test "${#DESKTOP_SHA256}" -eq 64
```

Expected: the artifact contains `hotel-desktop` and the versioned archive is non-empty. Record the SHA-256 for the release notes.

### Task 5: Publish and Audit the GitHub Release

**Files:**
- No source file changes
- GitHub Release: `v0.2.0`

**Interfaces:**
- Consumes: tag `v0.2.0`, `RELEASE_SHA`, packaged desktop artifact, and its SHA-256
- Produces: published GitHub Release with generated change notes and macOS aarch64 asset

- [ ] **Step 1: Create the release with generated notes and artifact metadata**

```bash
gh release create v0.2.0 \
  "$RELEASE_TMP_DIR/hotel-desktop-v0.2.0-macos-aarch64.tar.gz#hotel-desktop v0.2.0 macOS aarch64 (unsigned)" \
  --verify-tag \
  --title "v0.2.0" \
  --generate-notes \
  --notes "Production commit: $RELEASE_SHA

Desktop artifact: unsigned macOS aarch64 build.
SHA-256: $DESKTOP_SHA256"
```

Expected: GitHub publishes `v0.2.0` and uploads the archive with its exact SHA-256 in the notes.

- [ ] **Step 2: Audit tag, release, asset, repository, and production**

```bash
git ls-remote --tags origin refs/tags/v0.2.0 'refs/tags/v0.2.0^{}'
gh release view v0.2.0 --json isDraft,isPrerelease,tagName,targetCommitish,url,assets
git status --short --branch
curl --fail --silent --show-error https://saliminn.my/health
```

Expected: the peeled annotated tag resolves to `RELEASE_SHA`; the release is neither draft nor prerelease; the macOS archive is listed and downloadable; local `master` equals `origin/master`; the worktree is clean; production health is OK.
