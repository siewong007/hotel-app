# Full UI i18n Coverage — Implementation Plan (hotel-app)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every user-visible string in `hotel-web-fe/src` renders through the existing `Intl`-based i18n system with complete `en`/`ms`/`zh` translations; `tOr` fallbacks retired; coverage enforced by a new hardcoded-string audit test.

**Architecture:** Extend the existing system — `useTranslation(ns)` + `t()` in components, `resources/<locale>/<ns>.json` bundles, `errors:api.*` for backend codes. No new dependencies (ADR 012). Four new namespaces: `communications`, `promotions`, `ekyc`, `legal`.

**Tech Stack:** React 19, TS, Vite 8, MUI v9, Vitest, hand-rolled i18n on `Intl`.

**Spec:** `docs/superpowers/specs/2026-09-15-i18n-coverage-design.md` (approved).

## Global Constraints

Every task implicitly includes:

- Work in `hotel-web-fe/`. Locales `en` (source of truth), `ms`, `zh`. **Every key added to `en` MUST land in `ms` and `zh` in the same commit** — `resources.test.ts` fails otherwise.
- Conventions live in `docs/guides/internationalization.md` — read it first. `useTranslation('<ns>')` in components; bare `t` from `src/i18n` only in non-render code. `{{var}}` interpolation; plurals `_zero`/`_one`/`_other` (ms may omit `_one`). Never concatenate translated fragments.
- Reuse `common:*`/`status:*`/`validation:*` for identical concepts. Feature terms in the domain's namespace (map in spec §Namespace assignment).
- Enum/status values go through `formatStatusLabel` or `status:*` maps — never `replace(/_/g,' ')` (lint:strict bans it).
- Dates via `utils/date.ts`; numbers via `src/i18n` formatters; money via `utils/currency.ts` (not locale-aware — do not change).
- Do NOT translate: `features/legal/content/*` corpus (PDPA en/ms only — UI chrome still translates), DB/server content (guest/room/rate names, remarks, email copy), brand names, `MYR`/`RM`, `N/A`, `…`, `×`, keyboard glyphs, `routeTree.gen.ts`, `ds-bundle/`, `*.test.*`, `console.*`, developer-only errors.
- Hotel terminology: consistent per locale (folio, night audit, housekeeping, rate plan, OTA, walk-in, no-show, deposit, ledger, eKYC). Reuse terms already in `ms`/`zh` bundles before inventing new ones.
- Backend error codes → `errors:api.<code>`; unmapped → `errors:api.server_error`. Extend the map when a screen surfaces a real backend code.
- Gates per task (run from `hotel-web-fe/`, **sequentially — never two vitest suites at once**): `bun run typecheck && bun run lint:strict && bun run test`. `lint:strict` is `--max-warnings=0`.
- Commits: `feat(i18n): cover <domain>` / `test(i18n): …`. Conventional style per repo history.
- Translations: `ms` Bahasa Melayu; `zh` Simplified Chinese (`zh-CN` intlTag). Match the register already used in existing bundles (read `ms/common.json`, `zh/common.json` first for tone/terminology).

## Mechanical loop (every domain task, S1–S5)

- [ ] **S1** Scan every `*.tsx`/`*.ts` in scope for user-facing strings: JSX text, `placeholder`/`title`/`aria-label`/`alt`/`label`/`helperText`/MUI `headerName`, empty/loading/confirm/error/validation text, toast/snackbar messages, `tOr('k','fallback')` sites, enum label maps, table columns, menu items, `confirm()`/`window.confirm` text. Ignore exempt patterns per Global Constraints.
- [ ] **S2** Add keys to `en/<ns>.json` (semantic nested paths, `camelCase`), then translate into `ms/<ns>.json` and `zh/<ns>.json`. Reuse existing `common:`/`status:`/`validation:` keys where the concept matches.
- [ ] **S3** Replace literals with `t()`/`useTranslation`; convert `tOr('k','fallback')` → `t('k')` once the key exists in all three locales. Keep `formatStatusLabel`-style helpers for enums.
- [ ] **S4** Run gates sequentially; fix fallout (existing tests asserting English text should still pass — strings stay English under `en`).
- [ ] **S5** Commit `feat(i18n): cover <scope>`.
