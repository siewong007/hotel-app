# RPM bundle evaluation — SHIP

**Date:** 2026-09-19
**Decision:** SHIP — `.rpm` is now a default Linux bundle target with a
Fedora-container install smoke in `desktop-build.yml`.
**Evidence run:** `desktop-build.yml` run **35424550838**, Linux job, commit
`1852a750a` (the `rpm_eval=true` wiring from task 6 part 1).

## Evidence

- **Build:** `bun scripts/tauri-build.mjs --bundles deb,appimage,rpm`
  produced `Hotel Management System-1.0.0-1.x86_64.rpm` alongside the
  deb/appimage. The known tauri-bundler rpm-path hang
  (tauri-apps/tauri#15698, cli 2.11.4 pinned) did **not** trigger; the
  3600s `timeout` guard stays permanently regardless.
- **Package identity:** `hotel-management-system-1.0.0-1.x86_64`
  (kebab-cased `productName`, not `hotel-desktop` — that's the binary).
- **`rpm -qpR` declared deps** — two SONAME requires plus rpmlib markers:

  ```
  libwebkit2gtk-4.1.so.0()(64bit)
  libgtk-3.so.0()(64bit)
  rpmlib(CompressedFileNames) = 3.0.4-1
  rpmlib(FileDigests) = 4.6.0-1
  rpmlib(PayloadFilesHavePrefix) = 4.0-1
  ```

- **Install smoke (clean `fedora:41` container):** `dnf install -y`
  resolved a **314-package** transaction entirely from Fedora repos —
  webkit2gtk4.1 2.50.1-1.fc41, gtk3 3.24.43-2.fc41,
  javascriptcoregtk4.1, libcanberra-gtk3, etc. `rpm -q` →
  `hotel-management-system-1.0.0-1.x86_64`; `/usr/bin/hotel-desktop`
  present (18.8 MB); bundled `pgsql/bin/postgres --version` →
  `postgres (PostgreSQL) 19beta2`. `RPM install smoke: PASS`, exit 0.
- The run's only failure was the unrelated pre-existing deb-smoke
  `pg_dump` glob bug (fixed in `5af7b3926`).

## Why ship

- `tauri-bundler` 2.x writes `.rpm` in-process via the pure-Rust `rpm`
  crate — no `rpmbuild`/toolchain prerequisite beyond what the
  deb/appimage path already needs (the old "needs rpmbuild" notes in
  PACKAGING.md were stale v1 lore and are corrected).
- Declared deps are minimal and all resolve on current Fedora.
- The install smoke asserts the packaging contract (install, binary,
  bundled PG build) on a real RPM-native system — better than a
  host-side `rpm -i` on Ubuntu.

## Caveats / follow-ups

- **#15698 hang:** observed once upstream; our run was clean. The
  permanent `timeout` bounds it at 60 min of silence instead of the
  90-min job budget — if it ever fires, the build step exits 124 with
  "Bundling *.rpm" as the last line. A tauri-cli bump past 2.11.4 is
  the real fix when upstream lands it.
- Smoke verifies install + binary presence + bundled postgres, not a
  GUI launch (no display in the container); the deb smoke's xvfb probe
  covers the launch path on the same binary.
- `bun run build:rpm` (single-format local path) already exists in
  `hotel-desktop/package.json`.
